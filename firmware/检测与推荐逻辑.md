## 1. 系统概述

| 项 | 说明 |
|---|---|
| 硬件 | ESP32-S3-Touch-LCD-1.85C + AS7341 11 通道光谱传感器（f1~f8 可见光 + clear + NIR）+ TF 卡 + JD9853 触摸屏 |
| 屏幕 | 320×172 横屏（USB 口在右侧），LVGL 8.4，浅色主题，RGB565 色深 |
| 业务 | 用光谱传感器测量 PANTONE SkinTone 色卡/皮肤 → 得出皮肤颜色 → 推荐粉底液 + 口红 |
| 离线性 | 全流程离线运行：模型、色池、字体全部烧进固件，无网络 |

**色号编码规则**（PANTONE SkinTone，如 `3Y06SP`）：
- 第 1 位 `1~6`：肤深档（1 最浅 → 6 最深）
- 第 2 位 `R / Y`：底调（R=冷粉调 Cool，Y=暖金调 Warm）
- 第 3~4 位 `00~15`：类内深浅（14.5 为半档）
- 共 138 张有实测数据的色卡（官方库共 139 编号，4Y14SP 无数据）

**连续肤深刻度**（推荐算法用）：
```
dep16 = (dep - 1) * 16 + level + 8        # 0..104 的连续刻度
# 例: 3Y06SP → (3-1)*16 + 6 + 8 = 46
```

## 2. 检测流程（固件实测路径）

```
用户按 MEASURE
   │
   ▼
┌─────────────────────────────────────────────┐
│ 1. LED 补光：LED 8mA 亮 30ms                  │
│ 2. AS7341 采集 10 帧光谱                      │
│    配置: ATIME=29, ASTEP=599, GAIN=16X        │
│    每帧 10 通道: f1..f8, clear, nir           │
│ 3. 统计: 每通道 mean / std / CV(=std/mean)    │
│ 4. 质量校验: cv_max < 0.05 (稳定)             │
│    物理边界: sum(f1..f8) ≥ 200, clear ≥ 80    │
│ 5. 存 SD 卡 CSV + USB CDC JSONL 输出          │
└─────────────────────────────────────────────┘
   │
   ▼
9 维特征向量 (识别/模型的输入):
   spec8[0..7] = sqrt(f1..f8)，再归一化使 8 项和 = 1   ← 只用可见光 8 通道
   feat[8]     = ln( sum(f1..f8) )                    ← 亮度信息
```

关键结论（已实验验证）：**clear / NIR 通道是干扰源，剔除后只用 f1-f8 可见光 8 通道大幅提升精度**。

## 3. 皮肤色识别逻辑（两代方案）

### 3.1 V0.4 色号查表（当前固件，基准方案）

```
输入: spec8[8] (sqrt 归一化)
1. 与 138 张模板逐一算欧氏距离: d = Σ(spec8[i] - tpl.spec[i])² 开方
2. 距离最小的模板 → 色号 code
3. 显示颜色 = 模板内置的官方 sRGB → RGB565
   (官方色来源: PANTONE AdobeRGB1998 → sRGB 修正矩阵转换)
```

- 精度：留一交叉验证 **top-1 91.4% / top-3 97.1%**
- 误差性质：全部落在光谱几乎重合的相邻色号间（如 3Y05SP vs 4Y05SP 模板距离仅 0.0011），是 10 通道传感器的物理极限；对颜色显示和推荐**无实际影响**（相邻色号的官方色本身只差 ΔE<1）
- 查表版颜色误差极小：预测色 vs 官方色 ΔE 均值仅 0.12（因为颜色直接来自模板）

### 3.2 V0.5 模型直测（新版方案，正在设计 GUI 的对象）

**思路**：不再维护"138 卡模板数据集"，训练回归模型从光谱直接预测皮肤颜色，模型同时输出推荐所需的元数据（冷暖、肤深），一次前向得到全部结果。

```
输入:  feat[9] = spec8[8] + ln(sum)
归一化: x[i] = (feat[i] - x_mean[i]) / x_scale[i]
       (x_mean/x_scale 为训练集统计量，烧进固件)
网络:  9 → 20 (ReLU) → 5 (线性)，共 305 参数 (float32, ~1.2KB)
输出:  out[0..2] = R,G,B ∈ [0,1]  → ×255 → round → RGB565 量化后显示
       out[3]    = 冷暖得分       → >0.5 判为冷粉调(C)，否则暖金调(W)
       out[4]    = 肤深/104       → ×104 得 dep16 (0..104 连续肤深)
```

伪代码（与 JS/C 逐位一致）：
```python
def predict(feat9):                      # feat9 = spec8 + [ln_sum]
    h = [(v - MEAN[i]) / SCALE[i] for i, v in enumerate(feat9)]
    for L, (W, b) in enumerate(LAYERS):  # 2 层
        h = [b[j] + sum(h[i] * W[i][j] for i in range(len(h))) for j in range(len(b))]
        if L == 0: h = [max(0, v) for v in h]        # 隐层 ReLU
    r, g, b = (clamp(v, 0, 1) * 255 for v in h[:3])  # 输出层线性
    cool = h[3] > 0.5
    dep16 = h[4] * 104
    return rgb565(round(r), round(g), round(b)), cool, dep16
```

性能（5 折交叉验证，440 有效样本 / 138 卡）：
| 指标 | 数值 | 说明 |
|---|---|---|
| 颜色 ΔE76 均值 | 1.85 | 人眼几乎不可分辨（JND≈2.3） |
| ΔE p95 / max | 3.87 / 6.06 | |
| RGB MAE | 3.19 | 0..255 尺度 |
| 冷暖分类 | 98.9% (440 中错 1) | ← 推荐**不能**靠颜色距离判冷暖（C/W 池颜色太近会翻转），必须模型直接输出 |
| 肤深 dep16 MAE | 4.24 | 约 1/4 档 |

**与 V0.4 推荐一致性验证**（以 V0.4 官方查表推荐为基准，138 卡逐卡对比）：
- 粉底一致 85.5%、口红一致 85.5%
- 不一致的 20 例粉底中 **19 例为主推相邻 ±1 档**（屏显 3 格区间可覆盖，无业务影响）、1 例跨池（即唯一冷暖误判）、0 例跳档
- 结论：残余误差与查表版的"相邻色号物理极限"同性质，不影响推荐实质

## 4. 美妆推荐逻辑（V0.4 = V0.5 完全一致，仅元数据来源不同）

### 4.0 共用颜色数学（三端逐位一致，照抄即可）

```python
def rgb565(r, g, b):        # 888 → 565
    return ((r & 0xF8) << 8) | ((g & 0xFC) << 3) | (b >> 3)

def un565(c5):              # 565 → 888 (近似还原)
    r5, g6, b5 = (c5 >> 11) & 31, (c5 >> 5) & 63, c5 & 31
    return (r5 << 3 | r5 >> 2, g6 << 2 | g6 >> 4, b5 << 3 | b5 >> 2)

def lum565(c5):             # Rec.601 感知明度 0..255
    r, g, b = un565(c5)
    return (299*r + 587*g + 114*b) // 1000

def dist2(c5, r, g, b):     # RGB565 色距平方
    cr, cg, cb = un565(c5)
    return (cr-r)**2 + (cg-g)**2 + (cb-b)**2
```

> 注意：所有色池色值先 rgb565() 量化，再与同样量化后的皮肤色比较——保证屏幕上"看起来最近"的候选就是算法选出的那个。

### 4.1 粉底液推荐（巴黎欧莱雅 True Match，9 档 × 2 池）

选色体系：数字 = 深浅（1 浅 → 9 深），字母 = 底调（**C = 冷粉调 ↔ PANTONE R，W = 暖金调 ↔ PANTONE Y**）。

```python
FND_C = ["F3DED2","EDCFBF","E4BDA6","D9AB92","CB967A","B97F60","A4694C","8B553C","6D4030"]
FND_W = ["F4DEBC","ECD0A6","E2BD8E","D6A877","C69261","B47C4E","9D663E","825231","643D26"]
# 索引 i 对应色号 (i+1)C / (i+1)W，均 rgb565 量化后使用

def recommend_foundation(skin565, cool, dep16):   # dep16 仅备将来扩展，当前未用
    pool = FND_C if cool else FND_W
    r, g, b = un565(skin565)
    best = argmin(pool, lambda p: dist2(p, r, g, b))    # 主推 = 色距最近
    lo, hi = max(best-1, 0), min(best+1, 8)
    return {"main": pool[best], "range": [pool[lo], pool[best], pool[hi]]}
    # range = 深浅相邻两档，用于"试色区间"；V0.4 屏显 3 格，V0.5 屏显主推 1 格
```

### 4.2 口红推荐（18 支库，欧莱雅为主 + 经典大牌）

设计依据：
1. 底调匹配：R 肤配 cool 口红，Y 肤配 warm 口红
2. 肤深匹配：每支口红标注适用肤深档位区间 dmin~dmax（PANTONE 首位 1~6）
3. 明度匹配：口红普遍比肤色深一档 → 目标明度 = **肤色明度 − 25**，候选中选明度最接近的一支；不同肤色明度连续变化，推荐自然分散到不同色号，尽量"一肤一色"

def recommend_lipstick(skin565, cool, dep16):
    target = lum565(skin565) - 25
    cand  = [l for l in LIP if (l.cool if cool else l.warm)]          # ① 底调过滤
    inr   = [l for l in cand if l.dmin*16-8 <= dep16 <= l.dmax*16+8]  # ② 肤深区间(±0.5档容差)
    pool  = inr if inr else cand                                      # ③ 区间空则放宽

    return lip                                                        # 唯一一支

### 4.3 端到端数据流汇总

```
V0.4 (当前固件):
  光谱 → spec8 → 最近邻模板 → 色号 code ─┬→ 官方sRGB → RGB565 皮肤色
                                        └→ 解析 code 字符 (dep, R/Y) → 推荐参数

V0.5 (新 GUI 设计对象):
  光谱 → feat9 → MLP 模型 ─┬→ RGB → RGB565 皮肤色 (模型直出, 不查表)
                           ├→ cool (冷暖)
                           └→ dep16 (连续肤深)
                                    ↓ 三个量一起进推荐
                     recommend_foundation(...) + recommend_lipstick(...)
```

## 5. GUI 设计所需的可用数据项（每个环节产出）

| 环节 | 可显示的量 | 建议用途 |
|---|---|---|
| 采集 | 帧进度 n/10、CV 稳定度 | 测量页进度动画 |
| 识别 | 皮肤色 RGB565 / HEX | 结果页主视觉（大色块/圆形） |
| 识别 | 冷暖 (C/W) | 文字或图标（如"冷粉调/暖金调"） |
| 识别 | dep16 (0..104) | 肤深指示（如刻度条/档位圆点） |
| 粉底 | 主推色块 + 代码 (1C~9C/1W~9W) + 相邻 ±1 档区间 | 结果页推荐区 |
| 口红 | 色块 + 短码 + 产品全名 | 结果页推荐区（长名如 "MAC Velvet Teddy" 需考虑宽度） |
| 调试 | 官方色 vs 预测色 ΔE | 仅网页预览面板，固件可不显示 |

**必须保持的交互约束**（固件现状，重设计时可调整但需保留入口）：
- 任何子页有返回键回主页
- 主页可 LIST 选卡 / ◀▶ 换卡 / MEASURE 测量
- 测量完成自动进结果页；结果页返回回主页后可继续连测
- 138 卡序号 001~139 显示为三位数字（139 是官方编号总数）

## 6. 约束与经验教训（设计 GUI 时注意）

1. **屏幕优先级**：单帧静态显示 > 简单动画 > 音效；320×172 小屏信息密度有限，结果页聚焦"三个颜色"最有效
2. **字体**：中文用 Hiragino Sans GB 生成的点阵字库（font_zh_16），字库按需收录汉字——新 GUI 每多一个汉字都要重新生成字库，尽量复用现有 13 字 + "皮肤粉底口红"6 字；英文/数字用 LVGL 内置 montserrat
3. **LVGL 8.4**：recolor 语法 `#RRGGBB ` 后必须有空格；列表项过多会耗尽堆（已改用系统堆）
4. **冷暖判定禁止用颜色距离**：粉底 C/W 双池颜色本身极接近，±ΔE1.7 的模型误差会导致大量翻转——必须用模型第 4 路输出的分类结果（98.9% 准确）
5. **相邻色号误差无害**：屏显推荐区间（粉底 ±1 档）天然覆盖模型残余误差，GUI 上展示"主推 + 区间"比只展示单值更符合算法真实置信度
6. **颜色一致性**：所有显示色必须经 rgb565 量化后再比较/绘制，保证算法选择与屏幕渲染一致；打印对照表与屏幕显示使用同一 sRGB 色源
