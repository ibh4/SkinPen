## 1. 项目定位（一句话）

**SkinPen 是一支"皮肤色号检测笔"**：笔尖对准皮肤按一下，光谱传感器测量肤色，屏幕直接显示皮肤颜色，并离线推荐最适合的粉底液色号和口红色号。

解决的真实痛点：
- 柜台试色靠肉眼+自然光，误差大、不卫生；
- 线上买粉底/口红只能凭图片猜色号，色差退货率高；
- 专业测肤仪器（如 Pantone 皮肤色卡仪）昂贵，消费级方案缺失。

本项目用一颗 **~10 元级的多通道光谱传感器 + ESP32-S3**，在 5cm 内对任意肤色完成测量、匹配与美妆推荐，全程离线、单手操作、3 秒出结果。

## 2. 硬件平台

| 部件 | 型号/参数 | 说明 |
|---|---|---|
| 主控 | ESP32-S3（N16R8 级，16MB Flash / 8MB PSRAM） | ESP-IDF v5.5 框架，C 语言 |
| 屏幕 | 1.85 寸 LCD（JD9853 驱动），**320×172 横屏**，RGB565 | USB 口位于设备右侧 |
| 触摸 | AXS5106 电容触摸，I2C0 (GPIO41/42) | 坐标映射已校准：`swap_xy=1 + mirror_x=1 + mirror_y=1` |
| 光谱传感器 | **AS7341 11 通道**（f1~f8 可见光 415~680nm + clear + NIR + flicker），I2C 与触摸共用总线 | ATIME=29, ASTEP=599, GAIN=16X；SMUX 配置与 Adafruit 官方库一致；WHOAMI=0x24 |
| 补光 | 板载 LED | 采集时 8mA 亮 30ms 保证光照一致 |
| 存储 | TF 卡（SDMMC 挂载 `/sdcard`） | 保存测量 CSV + 色卡库配置 |
| 通信 | USB CDC | 输出 JSONL 实时数据流到 Mac |

关键硬件经验：
- AS7341 与触摸共享 I2C0，驱动需软恢复重试机制，实测稳定；
- 板上无 RTC，日期以 **2026-01-01 为开机基线**推进（数据目录 `/data/YYYYMMDD/`）；
- FATFS 必须启用长文件名（`CONFIG_FATFS_LFN_HEAP=y`），否则 fopen 长路径失败；
- LVGL 内存改用系统堆（`CONFIG_LV_MEM_CUSTOM=y`），解决 138 行列表堆耗尽。

## 3. 业务体系

### 3.1 PANTONE SkinTone 色卡体系

PANTONE SkinTone 是覆盖全人类的 110 种肤色标准化色卡。本项目实际使用其中 **139 个编号、138 个有实测数据**（4Y14SP 无数据）。

色号编码（如 `3Y06SP`）：
```
3   → 肤深档 1~6（1 最浅 → 6 最深）
Y   → 底调 R(冷粉调 Cool-Pink) / Y(暖金调 Warm-Gold)
06  → 类内深浅 00~15（14.5 为半档）
SP  → SkinTone 固定后缀
```
派生连续刻度：`dep16 = (dep-1)*16 + level + 8`，范围 0~104，供推荐算法做连续肤深匹配。

官方色值来源：photoshoplus 整理的 AdobeRGB1998 值 → **经实测比对的"A 修正矩阵"转 sRGB**（直接用标准转换矩阵整体偏绿，用户与实体色卡对比后选定 A 方案为标准，屏幕显示与打印对照表必须同源）。

### 3.2 美妆推荐体系（全部离线内置）

- **粉底液**：巴黎欧莱雅 True Match 选色体系——数字 1~9 = 深浅（1 浅→9 深），字母 C/W = 底调（C 冷粉调 ↔ PANTONE R；W 暖金调 ↔ PANTONE Y），共 **C 池 9 档 + W 池 9 档**。
- **口红**：多品牌库 **18 支**（欧莱雅纷泽 8 支为主 + MAC 4 + Dior 2 + 阿玛尼/TF/YSL 各 1），每支标注适用底调与肤深区间。
- 设计原则：**以巴黎欧莱雅产品优先推荐，无对应产品时用其他品牌补位**；尽量"一肤一色"（不同肤色明度连续变化，推荐自然分散）。

## 4. 项目演进时间线

| 版本 | 里程碑 |
|---|---|
| V0.1~V0.3 | 硬件 bring-up：LCD/触摸/TF/AS7341 驱动逐个打通；模块化固件骨架；横版 GUI（启动页/主页/选择页/测量页）；SD 卡 CSV 记录 + USB JSONL 流 |
| 数据采集 | 用 V0.3 固件对 138 张 PANTONE SkinTone 实体色卡逐一测量，每卡多次采样，累计 **678 条 records.csv** |
| 算法攻关 | 多轮特征工程实验后定型：**sqrt(f1-f8) 归一化 + 欧氏最近邻**，留一交叉验证 top-1 **91.4%** / top-3 **97.1%**；关键发现——**clear/NIR 通道是干扰源，剔除只用可见光 8 通道大幅提升**；残余误差全部落在光谱几乎重合的相邻色号间（如 3Y05SP vs 4Y05SP 模板距离仅 0.0011），属 10 通道传感器物理极限，且对推荐无实际影响 |
| V0.4（当前固件） | 查表识别 + 结果页美妆推荐：色号 → 官方色查表显示；粉底 3 格（浅/主推/深）+ 口红 1 格；18 支口红库上线；A4 打印对照表（300dpi PNG + img2pdf 无损 PDF，与屏显颜色同源一致） |
| V0.5（设计中） | **弃用"138 卡模板数据集"，改为训练回归模型从光谱直接预测肤色**：MLP 多任务输出 R/G/B + 冷暖 + 肤深，推荐算法不变；网页模拟器已完成双模式对比验证，GUI 确认后移植固件 |

## 5. 数据工程

```
采集 (V0.3 固件)
  LED 8mA 30ms → AS7341 读 10 帧 → mean/std/CV 统计
  → SD 卡 /data/YYYYMMDD/records.csv (678 条)
  → USB CDC JSONL 同步到 Mac
       │
清洗 (build_final.py / train_color_model.py 共用规则)
  cv_max < 0.05 (帧间稳定) + sum(f1..f8) ≥ 200 + clear ≥ 80 (物理边界)
  + 卡内 rdist ≤ 0.10 (离群剔除, 与卡中位数比较)
  → 有效样本 ~480 条 / 138 卡 (训练子集 440)
       │
资产生成
  ├─ skin_templates.h   138 模板 (spec8 向量 + 官方sRGB→RGB565) → V0.4 固件
  ├─ color_model.json   mlpB20/mt5 权重 + 均值/方差 + CV 指标 → V0.5 固件/网页
  └─ pantone_skintone.csv  139 条色卡库 (TF 卡 /config/ 同名, UTF-8 BOM 已兼容)
```

## 6. 算法现状（详细见《检测与推荐逻辑.md》）

| 方案 | 输入 | 输出 | 指标 |
|---|---|---|---|
| **V0.4 查表**（现固件） | spec8 (sqrt 归一化 8 维) | 色号 → 官方色 | top-1 91.4% / top-3 97.1%；显示色 ΔE 0.12 |
| **V0.5 模型**（新） | feat9 = spec8 + ln(sum) | R,G,B + 冷暖 + dep16（MLP 9→20→5, 305 参数） | ΔE 均值 1.85 / p95 3.87；RGB MAE 3.19；**冷暖 98.9%**；肤深 MAE 4.24 |

推荐环节两代完全一致（V0.5 仅元数据来源从"解析色号"变为"模型输出"）：
- 粉底：冷暖选池 → RGB565 色距最近为主推 + 相邻 ±1 档区间；
- 口红：底调过滤 + 肤深区间 → 明度最接近 (肤色明度−25) 的唯一一支，差 >40 放宽全池。

**V0.5 推荐一致性验证**（以 V0.4 官方查表推荐为基准，138 卡逐卡对比）：粉底 85.5% / 口红 85.5%；粉底 20 例不一致中 19 例为主推相邻 ±1 档（屏显区间覆盖，无业务影响）、1 例跨池（唯一冷暖误判）、0 例跳档——性质与查表版的相邻色号物理极限相同。
教训：**冷暖判定绝不能用颜色距离**（C/W 双池颜色太近，±ΔE1.7 误差即大量翻转），必须模型直接输出分类。
